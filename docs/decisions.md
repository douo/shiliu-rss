## 已被修订的提案

- 最初讨论的“重要源 1–2 分钟、普通源 15–60 分钟”已被用户撤回，不能继续作为性能目标。
- “摘要源自动补抓全文”已被用户撤回。长期存档只改变已获取内容的保存期限，不自动开启全文抓取。
- “所有源所有正文永远保存”已细化为按源保存；普通源清正文仍保留文章记录与整理成果。
- Go/SQLite 最初只是候选；D17 之后才完成工程比较并选定，不能倒写成产品访谈时已确认。
- 技术选型初稿的 Go 模板/原生 JS 页面已按 D20 改为 Svelte/TypeScript/Tailwind 静态前端。
- 初稿把端口登记泛化到 NAS；按 D19 修正为本机 APR 与 NAS 现有端口/台账各自管理。

## 随首版范围确认的设计约定

以下由设计者提出的约定已随产品文档整体确认；具体实现遵守这些约束：

1. 首版包含订阅/分类、收件箱、正文阅读、收藏/笔记/标签、归档搜索、源健康、保存设置、Agent token、迁移；暂不做自动摘要任务或额外客户端。
2. 普通源的 90 天从首次收录算起；迁移时尽可能保留旧系统首次收录时间，并应用已确认的 30 天迁移保护期。
3. 首次迁入已有源时默认普通保存，允许批量选择长期存档源；正式清理前给出按源的数量/范围预览。
4. 收藏和长期保存策略的变更只保护当前仍存在的内容。已清理正文可以显式尝试重新抓取；来源删除后无法保证恢复。普通源显式重新获取的正文从本次成功取得起另保留 90 天，普通轮询不重置期限。
5. API 首版提供有用途区分的 token；读取、保存摘要和触发全文是独立能力，不默认赋予删除数据或管理账号的能力。

## 本轮工程决定

这些是根据用户目标作出的工程选择，并非用户逐项指定的工具。完整理由、版本证据与边界见 [技术选型](technology.md) 和 [架构设计](architecture.md)。

| ID | 决定 | 关键原因 |
|---|---|---|
| T01 | Go 单进程模块化单体，SQLite WAL，pure Go 驱动 | 当前规模下优先维护简单、可重复构建；Rust 可行，未证明任何语言更省电 |
| T02 | Svelte 5 + TypeScript + SvelteKit 静态构建 + Tailwind CSS 4，按需 shadcn-svelte | 满足现代 Web 与简洁界面要求，NAS 无需 Node 服务 |
| T03 | OpenAPI 3.1、Go/TS 共享契约、HTTP JSON | 浏览器/Agent 共用业务规则，支持分页、增量、幂等与 scoped token |
| T04 | 持久调度/租约；默认 5h±1h；有界并发与失败重试 | 解决页面关闭仍能可靠更新及重启续作的问题 |
| T05 | FTS5 汉字拆分/短语匹配，contentless-delete | 支持两字中文词；清正文和索引同步，本机基础实验通过 |
| T06 | 单镜像，SSD 数据库，受控备份及日志轮换 | NAS 保持运行所需的配置/数据；开发测试产物留本机 |
| T07 | Miniflux 只读一致快照导出，在本机独立导入和核验 | 保证对账、幂等与 30 天保护；不影响正在使用的旧服务 |

## 实现阶段新增决定

| ID | 决定 | 证据与影响 |
|---|---|---|
| T08 | 使用readability官方继任v2、Lucide迁名包，保持技术栈 | 官方弃用/迁名提示；实际生成/构建/抓取/浏览器验证通过，版本锁文件随代码维护 |
| T09 | Kit3配置由Vite入口传入；静态启动脚本外置并预压缩 | 实际构建不接受旧配置；Go严格CSP曾拦内联bootstrap，外置后成品浏览器通过；不用unsafe-inline脚本 |

| T11 | FTS宽/稀疏查询采取有界候选判断 | 同规模中文宽查询从约1秒降到约32ms，不改字面匹配与到期规则 |
| T12 | schema升级前一致备份、future版本拒绝；同站冷却持久化 | v1→v2升级/失败回滚、备份失败拒启动、Retry-After重启及手动绕过测试通过 |
| T13 | Miniflux迁入旧hash与后续GUID匹配，特殊设置显式差异 | 上游2.3.0字段与GUIDhash证据，URL变化不重建文章；不假装兼容认证/重写等专有选项 |
