## 已被修订的提案

- 最初讨论的“重要源 1–2 分钟、普通源 15–60 分钟”已被用户撤回，不能继续作为性能目标。
- 旧阶段的“摘要源自动补抓全文”曾被撤回；本次 D27 明确引入**重要源晨报策略**例外。长期存档本身仍不触发全文抓取，不能把例外扩大到所有源。
- “所有源所有正文永远保存”已细化为按源保存；普通源清正文仍保留文章记录与整理成果。
- Go/SQLite 最初只是候选；D17 之后才完成工程比较并选定，不能倒写成产品访谈时已确认。
- 技术选型初稿的 Go 模板/原生 JS 页面已按 D20 改为 Svelte/TypeScript/Tailwind 静态前端。
- 初稿把端口登记泛化到 NAS；按 D19 修正为本机 APR 与 NAS 现有端口/台账各自管理。
- 初版的j/k、m/s/o、/、?单键导航按D23撤回；不要求用户关闭Vimium来使用阅读器。
- 随后统一Alt+Shift的方案也被用户否决：避免冲突不等于所有操作都必须组合键。↑/↓直接使用，其余从Vimium默认未绑定、且不是序列前缀的单键中选择；s未被Vimium默认占用，可用于收藏。

## 随首版范围确认的设计约定

以下由设计者提出的约定已随产品文档整体确认；具体实现遵守这些约束：

1. 原首版包含订阅/分类、收件箱、正文阅读、收藏/笔记/标签、归档搜索、源健康、保存设置、Agent token、迁移；当时暂不做自动摘要。D25 后自动摘要进入本次新阶段，额外客户端仍未纳入。
2. 普通源的 90 天从首次收录算起；迁移时尽可能保留旧系统首次收录时间，并应用已确认的 30 天迁移保护期。
3. 首次迁入已有源时默认普通保存，允许批量选择长期存档源；正式清理前给出按源的数量/范围预览。
4. 收藏和长期保存策略的变更只保护当前仍存在的内容。已清理正文可以显式尝试重新抓取；来源删除后无法保证恢复。普通源显式重新获取的正文从本次成功取得起另保留 90 天，普通轮询不重置期限。
5. API 首版提供有用途区分的 token；读取、保存摘要和触发全文是独立能力，不默认赋予删除数据或管理账号的能力。

## 本轮工程决定

这些是根据用户目标作出的工程选择，并非用户逐项指定的工具。完整理由、版本证据与边界见 [技术选型](technology.md) 和 [架构设计](architecture.md)。

| ID | 决定 | 关键原因 |
|---|---|---|
| T01 | Go 单进程模块化单体，SQLite WAL，pure Go 驱动 | 当前规模下优先维护简单、可重复构建；Rust 可行，未证明任何语言更省电 |
| T02 | Svelte 5 + TypeScript + SvelteKit 静态构建 + Tailwind CSS 4，按需 shadcn-svelte | 满足现代 Web 与简洁界面要求，NAS 无需 Node 服务 |
| T03 | OpenAPI 3.1、Go/TS 共享契约、HTTP JSON | 浏览器/Agent 共用业务规则，支持分页、增量、幂等与 scoped token |
| T04 | 持久调度/租约；默认 5h±1h；有界并发与失败重试 | 解决页面关闭仍能可靠更新及重启续作的问题 |
| T05 | FTS5 汉字拆分/短语匹配，contentless-delete | 支持两字中文词；清正文和索引同步，本机基础实验通过 |
| T06 | 单镜像，SSD 数据库，受控备份及日志轮换 | NAS 保持运行所需的配置/数据；开发测试产物留本机 |
| T07 | Miniflux 只读一致快照导出，在本机独立导入和核验 | 保证对账、幂等与 30 天保护；不影响正在使用的旧服务 |

## 内置 Agent 设计决定（已实现机制）

依据 D25–D29，详细取舍与实际取得的资料见 [Agent 设计](agent-design.md) / [调研](agent-research.md)。以下为工程决定，不是模型效果或性能验证。

| ID | 决定 | 原因与边界 |
|---|---|---|
| T16 | 重设计为内置模块，沿用 Go/SQLite/API，无新增权限体系 | 旧外部 API 缺少计划、报告与会话；未配置零调用，现有阅读能力不依赖模型 |
| T17 | 固定未读成员、逐篇/分块提炼、原分类/来源分层聚合 | 全部未读覆盖不能由 top-k 保证；保留状态账本、缓存/出处与可恢复步骤，缺文/预算不足明确 partial |
| T18 | evidence ID 输出、服务端渲染内部引用、版本化提示词/schema | 避免模型编造 URL/计数；结构合法性与语义支持分开验证 |
| T19 | 词法 RAG 与层次摘要先行，embedding/重排可选 | 复用当前 FTS，保留片段上下文；先测真实查询召回，再决定是否增加嵌入式向量索引，不引入独立向量服务 |
| T20 | 独立有界模型队列、续租/fencing、预算预留、断点恢复 | 现 Runner 的非feed分支是fulltext，不能直接混入Agent任务；不占源抓取槽，网络重复收费不作exactly-once承诺 |
| T21 | 重要源自动补抓不恢复已purged正文、不延长原保留钟 | 避免每日未读晨报绕过R-09/R-10；原始片段、索引/向量与任务输入同受正文有效期约束，释义成果保留 |

## D-30 · Responses 实际接入与简化执行器（2026-10-15）

用户提供已有服务的可用 Responses 流式示例，模型为 `gpt-6-luna`。当前同时支持 Responses 与 Chat Completions，默认前者，保留用户配置模型、不静默替换。Responses 请求含 `stream:true` / `store:false`，服务端解析 SSE，客户端以202+轮询避开请求超时。实际调用已验证 OK，并在隔离本机库通过两篇合成文章晨报与报告对话；不将这些小样本等同于语义质量/大规模费用验收。

执行器采用持久的确定流程：完整未读快照、分块卡片、来源层次归并；对话为单次有限检索计划+FTS片段+回答。不引入原提案的自主六步工具循环、向量/重排或新权限。该简化保留 R-19–R-22 的交付路径，召回质量增强独立评测。实际设计与边界已回写 agent-design.md，不能再将其记为设计未实现。

## D-31 · 晨报阅读首页（2026-10-16）

按用户实际使用反馈新增 R-24，修订 R-03：首页默认晨报，Agent 进入共享主侧栏。旧 `/agent` 深链转到同一首页工作区。报告引用携带 report/anchor，正文返回恢复相同报告及位置；标签页内仅保存位置数据，不保存正文。整份报告已读由共享业务 API 在一个短事务内更新文章状态、版本、changes 与幂等结果，范围由服务端成员卡片判定，不依赖浏览器已加载的50篇。运行中拒绝批量操作；部分完成的报告可操作已实际总结的部分。

迁移后源站仍提供、旧快照已经不含的历史文章可能作为新文章入库，无法推断其旧阅读状态。应核对身份、同源 URL 和 changes，不能凭计数差异擅自全标已读。真实数据计数保留在私有台账。

## D-32 · 晨报末尾操作与页内提问（2026-10-16）

按用户反馈新增R-25。已读操作在读完报告后呈现；运行和范围说明用可悬停、聚焦及点击的浮层提供，浮层进入顶层以免被滚动容器裁切，并适配小屏、Escape与点击外部关闭。技术报告区分已处理/实质摘要/全文依据与聚合状态；旧报告缺失的原因保持未知。新聚合失败只记录阶段、来源ID与稳定错误码，不记录服务响应正文或凭据，并标明展示截断；不在这次交互修订中宣称解决全部聚合质量与恢复问题。

报告对话复用原会话API，在当前工作区右侧或窄屏底部展开，延迟到首条问题才创建会话；关闭后重新打开复用关联会话，后台回答可继续。独立对话和页内提问共用消息组件，保持报告阅读/正文返回的路由与位置机制。主题文字对比、元信息字号和页面左右对齐一并修订。

## D-33 · 侧栏异常详情与分类子源（2026-10-16）

R-26沿用Feed API已有error与调度时间，不新增请求或自行猜测网络根因。通用悬停浮层增加橙点入口，源导航与异常按钮为相邻控件，避免嵌套按钮或查看异常时误导航；Escape先关闭浮层，手机导航保持展开。分类箭头与分类文章入口分开，各分类按当前feeds的category_id派生子源，复用相同源行/异常组件；展开状态仅在当前会话内保留。没有引入多级分类数据模型或改变分类业务规则。

## D-34 · 文章按发布时间排序与源未读数（2026-10-16）

R-27将ListArticles从首次收录时间改为COALESCE(published_at,first_seen_at)及ID倒序，使迁入与同批抓取文章按页面显示日期排列；网页和API共享规则。游标加入published版本标识，旧游标返回400需从第一页重启，避免解释成不同含义。保留收录时间和原时间筛选语义，不更改生命周期或晨报快照。新索引覆盖全局/按源排序与按源未读统计，schema升级至4，仍由既有升级前一致备份保护。

Feed接口增加只读unread_count：包含归档、排除removed，与全量未读查询一致，不按首页已加载条目推算。两种侧栏源行复用同一字段；更新列表、单篇状态变更、本页批量及晨报批量已读后更新服务端统计，0不展示。不引入额外计数缓存或逐源网络请求。

## D-35 · 列表详情及全量未读标签（2026-10-16）
