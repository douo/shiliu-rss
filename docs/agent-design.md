# 内置 Agent 系统设计与实现

更新：2026-10-15。R-19–R-23 的配置、晨报、对话、外部 API 已实现。调研依据见 [研究记录](agent-research.md)，实际验证和剩余质量评测见 [实施记录](implementation.md)。此文说明当前实现；模型摘要质量不等于程序覆盖校验。

## 产品与入口

一个活动模型配置、一个模型执行槽，和阅读器运行在同一个 Go 进程。未配置地址/模型或关闭开关时停用，已有文章、报告和对话仍可读取。模型调用不成为 RSS 抓取和普通阅读的必经路径。不增加角色、权限矩阵、Agent scopes 或审批；新接口复用现有会话或可撤销 token。

侧栏的 Agent 进入 `/agent`，提供晨报、对话、模型配置；原设置页也有 Agent 配置。配置包含 Base URL、协议、原样使用的模型名、只写密钥、输出模式、上下文与输出限制、每天时间/时区、运行窗口及日 token/调用上限。Base URL 推荐填写包含 `/v1` 的 API 前缀；也兼容直接填 `/v1/responses` 或 `/v1/chat/completions`。

Responses 使用 `instructions`、JSON 编码的 `input`、`stream:true`、`store:false`，解析 SSE 文本增量、结束状态和 usage。另支持流式 Chat Completions。输出模式默认提示词约束 JSON，也可显式选择 JSON Object / JSON Schema；不静默替换协议或模型。模型客户端直连配置的地址，符合本次 LAN 网关调用方式；不把凭据带到重定向位置。

Key 留空保留已有值；可明确清除。数据库文件权限为 0600，响应只含 `key_configured`；也支持服务端 `SHILIU_AGENT_API_KEY_FILE`，设置此变量时优先读取该文件。请求、认证头、原始正文和模型错误响应不写日志。模型错误只显示稳定状态码。

## 晨报流水线

1. 默认每天 Asia/Shanghai 08:00。启用/修改配置后安排下一次；重启错过时段则合并成最近一份，不重放停机期间每天的任务。计划键为配置版本加本地日期，重复 tick 不重复建报。
2. 在短事务内固定全部 `read_at IS NULL AND removed=0` 的文章 ID、标题、源/分类/重要度及 hash，包含归档/暂停源。记录截止时间与 changes 高水位。新到文章不混进正在处理的集合，后来标已读也不移出该报告。
3. 按重要度优先、同级源轮转取一批成员。默认重要/普通/次要三级，源默认普通；设置页可编辑，也可对当前筛选出的源批量设置。
4. 重要源优先现存全文。缺少时只允许尚在保留期、未被清理的文章通过原全文任务队列补抓；复用同篇已有任务，包括已失败的尝试，不每天重新发起无限补抓。网络并发、同站 gate、冷却及提取器均复用现有执行器。
5. 自动补抓在完成事务中再次检查有效期和清理状态，不恢复已清理内容，不重置原来的 90 天时钟。显式按钮/API 获取仍遵循原 R-10。缺文或失败按已有资料处理，并将该成员标为降级，报告为 partial。
6. 重要源全文遍历所有分块，每块提炼后进行有界层次归并；不静默截去长文中段。普通默认 3,000 字符，次要 500，可将次要设为 0 而仅用标题。普通/次要小批提炼，根据保守上下文估计缩小批次。
7. 成员卡片按模型/协议、提示词版本、文章 ID/标题、实际内容 hash、深度与截取策略缓存；次日持续未读仍计入总数，未变化的卡片直接复用。分类变化重建分组，不强迫重复读原文。
8. 固定原分类和来源，不让模型决定丢弃哪一个源。分类按最高重要度、加权未读量（重要4/普通2/次要1）排序；分类内按重要度、未读量、稳定 ID 排序。来源卡片分批汇总，资料多时继续按层归并，每层输出最多两个主题块。最终每源保留最多八块；原卡片和全体成员均可分页查看。
9. 计数、进度、来源标题和分组由程序提供；模型只生成释义段落。总数、新提炼、复用、全文、降级、不可用、待处理分别展示。预算/时限/格式失败输出部分报告与缺口，已完成卡片保留，支持续作。

生成和查看报告不标记文章已读。点击内部引用进入原来的阅读页时，沿用阅读页既有已读行为。

## 对话与 RAG

当前使用固定的有界检索流程，避免为本轮需求引入任意工具执行器：

- 先读取数据库精确全库数量、源健康/各源未读数。源明细最多 30 项，优先问题点名的源，其余按故障/未读量；明示明细范围，不能当作全部来源清单。
- 模型只提取最多三个短字面短语及最多五个明确数字文章 ID。服务端验证参数，模型不能输出 SQL、Shell、URL 或新工具。
- 用现有 FTS 找候选，最多十二篇，按词法匹配从当前有效内容取每篇最多三个片段，再按上下文空间限制输入。没有复制一份永久正文片段库；正文到期后即时不参与检索，即使清理任务尚未运行。
- 报告对话读取截止统计和有限的释义摘要；检索 SQL 在 LIMIT 前约束到该报告成员集合。报告内容和当前计数分别标明。
- 历史只传最近六条消息的有限文本。临时证据和原始 prompt 不持久化；用户消息、检索操作说明、生成后的释义与引用保留。
- 统一回答提示词区分事实、分析、限制。精确计数依赖数据库，top-k 只代表本次找到的资料；完整未读综合必须生成晨报，不能把对话检索冒充全集总结。

六步自主 planner、多查询 RRF、语义 embedding、重排、长期会话摘要及全库向量均未引入。它们属于后续召回质量增强，不能写成现有功能。当前词法方案的真实召回率与大规模摘要语义质量尚需金标准评测。

## 结构化输出与引用

实际提示词位于 `internal/agent/prompts/`，版本 `shiliu-agent/3`。固定 system 指令与任务指令独立于 JSON 编码的文章/标题/历史等资料。外部文字无修改配置或调用工具的能力。

文章输出使用 article-batch schema；报告/回答使用 narrative schema。服务端拒绝额外字段、尾随 JSON、未知/跨文章 ID、事实/分析无依据、HTML、URL 与 Markdown 链接。格式有一次修复机会；失败不以自由文本绕过。事实支持、指令注入抵抗和代表性仍需语义评估，结构验证不能证明事实都正确。

永久输出为释义摘要、ID/hash、依据类型和系统计数。引用 URL 由服务端从文章 ID 生成 `/?scope=all&article=<id>`，模型不生成 URL。正文型卡片提交前再次校验 hash/有效期。正文清理覆盖原 FTS；Agent 不保存独立的原文 prompt/片段缓存，释义产物按整理成果保留。

## 持久化、预算与恢复

迁移 v3 增加 `feeds.importance`、全文任务 reason 和六张表：`agent_settings`、`agent_runs`、`agent_steps`、`report_members`、`agent_conversations`、`agent_messages`。旧库升级前执行原有一致性备份；新功能默认未配置/停用，不改变文章阅读/收藏/笔记。

Agent 队列独立于 feed/fulltext 队列；一个模型槽，对话优先。每轮报告批次后重新排队。租约 120 秒，每 25 秒续约，写入检查 fencing token、配置版本和租约。取消或配置修改使旧响应不能发布。步骤结果持久化，重启恢复时复用已验证的派生输出，用户消息幂等，不保存原始模型输入。

默认日上限 1,000,000 token、200 次请求，运行窗口 30 分钟。请求前原子预留 UTF-8 字节估计加最大输出，usage 存在时结算，未知/中断按预留保守记账；这不是金额估算。每次格式修复、重试、对话都计入。单请求超时 100 秒；短暂故障最多三次尝试，长 Retry-After 持久延后，在任务运行窗口和日调用上限内继续。配置/鉴权错误不自动循环。预算耗尽不会通过点击重试绕过。

## 已发布 API

唯一契约源为 `api/openapi.yaml`，Go 与 TS 均由其生成。基础路径 `/api/v1/agent`；写入复用 CSRF/现有 token。模型任务返回 202，客户端轮询 run，不占用现有 30 秒 HTTP 写入超时。

| 路径 | 行为 |
|---|---|
| `GET/PUT /settings`、`GET /usage` | 配置、只写 Key、配置版本与今日账本 |
| `POST /connection-tests` | 通过当前设置异步进行结构化输出连接测试 |
| `POST /report-runs` | 固定全集并排队晨报；Idempotency-Key |
| `GET /runs?kind=report&before=...`、`GET /runs/{id}` | 历史元数据、任务/报告详情 |
| `POST /runs/{id}/control` | `action=cancel/retry`，保留已完成步骤 |
| `GET /reports/{id}/members?after=...&limit=...` | 固定成员与卡片，最多200项 |
| `PUT /reports/{id}/result` | 外部提交结构化报告；验证成员/hash/分组/内部引用，不能伪造覆盖数 |
| `GET/POST /conversations` | 会话历史/新建，可关联 report_id |
| `GET/POST /conversations/{id}/messages` | 消息分页/幂等发送 |
| `POST /queries` | 外部无状态查询，共用有界 RAG 与回答管线 |

外部汇报先创建报告快照、取消内置执行，再提交 result；正在执行的 run 返回冲突。外部自报的阅读范围不认证为内置处理完成，报告标明外部/partial；覆盖数读取真实成员账本。系统字段重建，不接受伪造 URL 或组总数。

用户已追加授权 NAS 部署与全量迁移/Miniflux 切换，执行见 production.md。Agent 模块范围不含推送、自动已读、多 Agent 协作、自动更换模型或新的权限系统。
