# 安全与敏感数据

拾流保存订阅地址、阅读记录、文章和模型凭据。运行配置、数据库与备份需要限制访问权限。

## 凭据与配置

- 密码、API Key、bearer token、会话 cookie 和 SSH/TLS 私钥不写入源码、日志或 issue。
- `deploy/.env.example` 和 `deploy/reader.env.example` 提供配置模板；实际 `.env`、`reader.env` 不纳入版本控制。
- 数据目录权限设为 0700，配置、数据库和备份文件按 0600 管理；容器挂载文件需允许运行 UID 读取。
- Agent Key 在设置中只写不回显，留空保留已有值，也可通过 `SHILIU_AGENT_API_KEY_FILE` 读取受保护文件。日志不记录 Authorization、请求资料或模型错误原文。
- Key 不放入 URL、浏览器持久存储或命令行参数。凭据泄露后应先撤销或轮换。

## 仓库内容

仓库保存源码、合成测试数据、文档和配置模板。数据库及 WAL/SHM、订阅导出、快照、备份、认证状态和包含真实内容的截图或 trace 不纳入版本控制。示例使用保留域名及占位路径。

`config/dev.env` 只包含回环监听、固定开发端口和相对数据路径，可随代码维护。忽略规则不能移除已被 Git 跟踪的文件。镜像构建上下文仅包含 Linux 二进制和 Dockerfile。

可在提交和发布前检查当前文件及历史：

```sh
./scripts/check-privacy
./scripts/check-privacy --history
gitleaks git --redact --no-banner
```

内置检查依赖 Python 标准库和 Git，覆盖常见密钥格式、个人 home 路径、文档私网示例和环境标识；`--history` 检查所有本地 ref 可达的 blob。输出只含位置和规则，不显示值。启发式检查需结合独立密钥扫描和内容审阅使用。

秘密曾提交到历史时，删除最新文件不足以移除旧版本。撤销或轮换凭据后，协调受影响的分支、标签与协作者，再清理历史并检查构建产物和缓存。

## 应用与备份

外部 HTML 在呈现前净化，普通字段转义，源和文章链接只允许 HTTP/HTTPS。文章内容作为 Agent 的资料处理，不能授权修改配置或调用工具。数据查询、正文有效期、token 撤销、CSRF、幂等和版本冲突由服务端执行。

数据库及 WAL/SHM 放在同机本地文件系统。备份包含与数据库相同的敏感数据，需限制访问并按保留期限轮换。正文清理使内容在应用和检索中不可见；WAL、空闲页及轮换期内备份可能仍有副本，不属于取证级擦除。

语义注入抵抗、摘要真实性和检索召回需单独评估，JSON 格式及引用合法性校验不能证明模型结论正确。
