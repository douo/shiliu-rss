# 安全与仓库脱敏

本项目保存私人订阅、阅读状态和文章，Git 仓库只保存源码、合成夹具、通用文档与无凭据的配置示例。私有仓库也需要脱敏，不能把可见性当作秘密管理。

## 不提交的内容

- API Key、密码/哈希、bearer token、会话 cookie、CSRF 值、SSH/TLS 私钥及认证状态。
- `.env`、`reader.env` 等实际运行配置，数据库/WAL/SHM、快照、导出、备份和完整容器环境。
- 带订阅 token 的 URL、真实正文、阅读记录、生产截图/trace、原始模型资料和响应。
- 私人域名、内网模型网关、主机/端口/存储台账、环境登记 ID 及真实实例统计。

这些内容留在受保护的 `.local/` 或独立运维秘密存储；目录权限 0700，凭据/快照按 0600 管理。忽略规则覆盖常见数据与认证文件，但已经被 Git 跟踪的文件仍需主动处理。发布镜像的构建上下文仅允许 Linux 二进制与 Dockerfile，避免包含开发库和凭据。

## 示例和运行配置

示例使用 `example.com` / `example.invalid` / `internal.example` 或明确占位路径，不复用个人实例地址。RFC1918 网络地址可以是专门的 SSRF 测试向量，不应作为界面中的私人网关示例。

`config/dev.env` 是允许跟踪的例外，仅有回环监听、固定开发端口和本机相对数据路径。`deploy/.env.example` 不含秘密，复制后填写自己的镜像、HTTPS 地址、端口与备份路径。系统服务模板的目录也需与实际配置匹配。

Agent Key 只写不回显，留空保留；存储在受保护数据库或 `SHILIU_AGENT_API_KEY_FILE`。日志不记录 Authorization、请求资料或模型错误原文。不要把 Key 放 URL、浏览器持久存储、进程参数或 issue。

## 发布检查

```sh
./scripts/check-privacy
./scripts/check-privacy --history
gitleaks git --redact --no-banner
```

内置检查只依赖 Python 标准库和 Git，覆盖跟踪文件、常见密钥格式、个人 home 路径、界面/文档私网示例和环境标识；`--history` 检查所有本地 ref 可达的 blob，输出只含位置和规则，不显示值。它是有限的启发式检查，不能证明不存在任意格式的秘密；用独立密钥扫描器和人工内容审阅补足。

首次 GitHub 发布前已用 Gitleaks v8.30.1 检查原始完整历史，未发现密钥；另行发现并脱敏了私人运维记录、环境地址与登记标识。原始文档和 Git bundle 仅保留在忽略的本机私有目录。历史中含实例信息的旧文档替换为脱敏说明，其余地址/标识统一清理；提交作者使用 GitHub noreply 邮箱，顺序保留而提交哈希变化。

推送仅明确指定已审查分支，避免 `--mirror` 或 `--all` 意外发布备份 ref。原始 bundle、历史映射、扫描报告和凭据不上传。源码中的测试账号及鉴权样本均为合成数据，不是可用实例凭据。

## 后续发现泄露

若秘密曾推送，先撤销/轮换实际凭据，再清理所有受影响分支、标签和相关缓存/构建产物；删除最新文件不能移除 Git 历史。清理历史前留受保护恢复依据，与已有协作者协调哈希变化，重新扫描要推送的完整 ref。不要将发现的秘密复制到公开 issue 或提交说明。

## 应用边界

外部 HTML 需净化，普通字段转义，源/文章链接只允许 HTTP/HTTPS。外部内容不能给 Agent 下达系统指令。精确数据查询、正文有效期、可撤销 token、CSRF、幂等和版本冲突由服务端统一执行；不增加独立的 Agent 权限体系。

数据库和备份包含敏感数据，应放本地文件系统并限制权限。正文清理是应用层删除与检索不可见，不是取证级擦除；WAL、空闲页和轮换期内备份仍需按敏感数据保护。语义注入抵抗、摘要真实性与检索召回不能仅靠 JSON 格式校验证明。
